# AI 写词与作曲方案二任务清单

依据第二版 PRD 和方案二技术文档。每项按一次对话／一次提交拆分，完成所列依赖后即可开始；编号是建议执行顺序。仅实现中文歌词、钢琴旋律与简单伴奏、试听和 MP3 下载。

下列函数和检查入口是待实现的验收约定，不是当前已有功能。每个后端任务交付时附一个可直接运行的示例或检查命令，便于亲自验证。

| 编号 | 任务 | 必须先完成 | 怎么算做完 |
|---|---|---|---|
| 01 | 初始化 React/Vite 前端、FastAPI 后端及本地启动说明 | 无 | 按说明启动；打开前端看到首页占位；调用 `/api/health` 返回 `{"status":"ok"}`。 |
| 02 | 配置 FluidSynth、FFmpeg 和可使用的钢琴 SF2 音源 | 01 | 运行环境检查显示两个程序及音源可用；移除音源配置，提示具体缺失项。 |
| 03 | 定义输入、歌词、音乐规划、乐谱和任务数据格式 | 01 | 校验示例乐谱通过；将音高设为 128 或时值设为 0，返回明确字段错误；歌词结果少于三版时拒绝。 |
| 04 | 写入预设、七种风格规则及默认音乐规划 | 03 | 检查命令列出 PRD 的全部预设；每种风格的模板 ID 均能找到对应规则；未知风格 ID 被拒绝。 |
| 05 | 实现乐谱 JSON 导出 MIDI | 03 | 输入中央 C、起点 0、时长 480 tick、120 BPM；读回 MIDI 得到一拍、约 0.5 秒；旋律和伴奏为独立轨道。 |
| 06 | 实现 MIDI 渲染钢琴 WAV | 02、05 | 渲染测试旋律与和弦，打开 WAV 能听到两部分；文件非空，无明显爆音；缺音源时返回错误。 |
| 07 | 实现 WAV 转 MP3 与成品检查 | 06 | 转换测试 WAV，MP3 可播放；检查能报告时长；超出 45～75 秒的测试成品不能标记成功。 |
| 08 | 实现歌词标题识别、分句和字符映射 | 03 | 输入 `[主歌]\n夏夜的风\n[副歌]\n一起向前走`，得到两个段落及对应歌词行；缺副歌标题时提示补齐，不改原文。 |
| 09 | 实现段落时长与歌词节奏分配 | 04、08 | 24 小节、4/4、100 BPM 输出 57.6 秒乐谱时长，另计尾音；短歌词有句间停顿；明显过长的输入提示缩短，不删词。 |
| 10 | 实现主旋律规则与副歌变化 | 09 | 同一输入、规则版本和种子得到相同音符；音符不越音域，单声部无意外重叠；副歌在音区或节奏上与主歌可辨识。 |
| 11 | 实现简单和弦伴奏与自然结尾 | 10 | 合成一版完整小样：伴奏与旋律对齐，旋律可听清，结尾稳定且无硬切；说唱样例以节奏和简单动机为主。 |
| 12 | 接入文本模型适配层及配置 | 03 | 配好后端密钥后，示例请求返回结构化数据；错误密钥或超时得到明确错误；浏览器代码和响应中不含密钥。 |
| 13 | 实现三版歌词生成接口 | 04、12 | 调用 `POST /api/lyrics`，返回故事叙述、情绪表达、意象表达三版中文歌词，均有主歌、副歌；请求失败可重试。 |
| 14 | 实现 AI 音乐规划与默认规划回退 | 04、08、12 | 正常规划只引用已有模板；注入未知模板 ID，最多修复一次，再使用可通过校验的默认规划；过程可查看内部记录。 |
| 15 | 实现 SQLite 任务存储及提交／查询接口 | 03 | 提交任务得到 ID，查询为 `queued`；同一 `requestId` 重复提交返回同一 ID；编辑后提交的新任务保存新歌词快照。 |
| 16 | 实现单 worker，串联规划、作曲与渲染 | 07、11、14、15 | 提交真实任务，状态按 `queued→running→succeeded` 变化，得到 45～75 秒 MP3；渲染中仍可调用健康接口。 |
| 17 | 实现任务失败、重启处理与独立文件目录 | 16 | 模拟渲染失败，任务为 `failed`；中断 worker 后重启，遗留运行任务变失败；新任务文件不覆盖上一次成功音频。 |
| 18 | 实现音频播放与下载接口 | 16 | 浏览器打开音频可播放；带 Range 的请求返回对应片段；下载得到可播放 MP3，与试听使用同一文件。 |
| 19 | 实现创作表单并接歌词生成接口 | 04、13 | 首页显示全部预设；未选必填项无法提交；故事可留空；点击生成显示等待状态，成功展示三版，失败保留输入。 |
| 20 | 实现歌词选择与手动编辑 | 19 | 任意选择一版可编辑；修改文字后提交载荷包含最新歌词；空歌词禁止作曲；再次选定别版时明确切换编辑对象。 |
| 21 | 接入音乐任务、播放器和下载按钮 | 18、20 | 编辑后生成，显示进度状态；成功可播放、暂停、拖动和下载；页面标注“钢琴旋律与伴奏小样，无人声演唱”。 |
| 22 | 实现重新生成与旧结果保护 | 17、21 | 重新生成创建新任务和种子；失败保留旧播放器；修改输入显示需重新生成提示；模拟旧请求晚返回，不覆盖新结果。 |
| 23 | 验证七种风格并调整配置 | 22 | 各生成一版短歌词小样，逐一试听，均含主歌、副歌和自然结尾、时长合格；记录情绪、节奏及歌词适配的实际效果，修正明显问题。 |
| 24 | 完成本地运行说明与最终流程验收 | 23 | 从干净环境按说明启动前端、后端和 worker；走通“输入→三版歌词→编辑→作曲→试听→下载→重新生成”，失败后可重试且内容保留。 |

实施顺序：先用固定乐谱打通声音管线（05～07），再验证规则作曲（08～11），之后接入 AI 与页面。文本模型和钢琴音源分别在 12、02 中确定，不增加用户选模型或音源的功能。

验收注意：检查通过只能证明时长、数据和播放正常；“好听、符合情绪、歌词适配”须试听，必要时跟着旋律试唱。若规则小样效果不合格，应在 11 中先修正，再推进后续集成。
